1. 版本与结论

这次拉的是 Physical-Intelligence/openpi，commit 215abfb，约 12.5k 行 Python。仓库不是单一模型，而是同时包含三代：

模型类型骨干/动作头配置
π0flow matching VLAPaliGemma 2B + Gemma 300M action expertPi0Config()
π0-FAST自回归 VLAPaliGemma 2B + FAST action tokenizerPi0FASTConfig()
π0.5flow matching VLAPaliGemma 2B + action expert，adaRMS + 离散 statePi0Config(pi05=True)

最新的是 π0.5。 仓库里默认的 ALOHA / DROID / LIBERO 推理 checkpoint 基本都是 pi05_*；只有 ALOHA_SIM 的默认还是 pi0_aloha_sim。

3.1 PaliGemma + action expert

π0 是 PaliGemma + action expert 的 flow matching VLA：

  • PaliGemma 2B：SigLIP So400m/14 视觉编码器 + Gemma 2B 语言模型
  • Action expert：Gemma 300M，单独一套权重，和 PaliGemma 同深度（18 层），宽度 1024
  • 输入三路图像：base_0_rgb、left_wrist_0_rgb、right_wrist_0_rgb，224×224
  • 动作：action_dim=32，action_horizon=50
llm = nnx_bridge.ToNNX(
    _gemma.Module(
        configs=[paligemma_config, action_expert_config],
        embed_dtype=config.dtype,
        adarms=config.pi05,
    )
)

gemma.Module 支持多个 expert，每个 expert 有自己的权重，token 按 expert 路由。

3.2 输入序列怎么拼

Prefix（图像 + 指令）：

3 张图 × 每张 256 token = 768 个 image token
prompt 最多 48 个 text token
prefix = 768 + 48 = 816 个 token

Suffix（状态 + 动作）：

π0:
  1 个 state token
  50 个 action token
  suffix = 1 + 50 = 51 个 token

π0.5:
  state 离散化后放进 prompt
  suffix = 50 个 action token

整体序列：

π0:   [prefix 816] + [suffix 51] = 867 个 token
π0.5: [prefix 968] + [suffix 50] = 1018 个 token

time 怎么进去：

  • π0：time embedding 不是单独 token，而是拼到每个 action token 的特征上：1024 + 1024 → MLP → 1024。
  • π0.5：time 通过 adaRMSNorm 注入 action expert，不拼到 token 上。

Attention 谁看谁：

Query能看
prefixprefix（full attention）
stateprefix + state
actionprefix + state + 所有 action

也就是说：prefix 不能看 suffix；state 不能看 action；action 能看 prefix、state 和所有 action。这是 block-level causal，block 内是 full attention。

make_attn_mask 就是在实现这个 block 边界：

attn_mask = cumsum[:, None, :] <= cumsum[:, :, None]
valid_mask = input_mask[:, None, :] * input_mask[:, :, None]
return jnp.logical_and(attn_mask, valid_mask)

3.2.1 不是 causal，是 block-causal

整个序列不是标准 causal mask。准确说是 block-causal：

Queryprefixstateaction
prefix✓✗✗
state✓✓✗
action✓✓✓
  • prefix 内部是双向 full attention：第 1 个 image token 能看最后一个 text token，反过来也能看。
  • prefix 看不到 suffix：prefix 的 query 只能看 prefix 的 key。
  • state 能看 prefix + state，不能看 action。
  • action 能看 prefix + state + 所有 action；action 之间也是双向 full attention，不是 token-level causal。

ar_mask 标记的是 block 边界，不是 token 级 causal：

prefix: 0 0 0 ... 0     -> block 0
state:  1               -> block 1
action: 1 0 0 ... 0     -> block 2

所以 cumsum 得到 block id 0/1/2，block[j] <= block[i] 就得到上面这张 block-lower-triangular 的 mask。

π0.5 少一个 state block：prefix 只能看 prefix，action 能看 prefix + 所有 action。

3.3 Flow matching loss

compute_loss（pi0.py:189）：

\[ x_t = t \cdot \epsilon + (1-t) \cdot a,\quad u_t = \epsilon - a \]
\[ \mathcal{L} = \| v_\theta(x_t,t) - u_t \|^2 \]
x_t = time_expanded * noise + (1 - time_expanded) * actions
u_t = noise - actions
v_t = self.action_out_proj(suffix_out[:, -self.action_horizon :])
return jnp.mean(jnp.square(v_t - u_t), axis=-1)

t 采样是 Beta(1.5, 1) * 0.999 + 0.001。

3.4 Sampling

sample_actions（pi0.py:217）：

  • 先跑 prefix，填 KV cache
  • 从 t=1 到 t=0，默认 10 步
  • 每步 x_t += dt * v_t
  • 注意代码里 t=1 是噪声、t=0 是目标，和论文相反，注释里也写了

4. π0-FAST

核心文件：

src/openpi/models/pi0_fast.py:134   class Pi0FAST

π0-FAST 是 自回归 VLA，没有 action expert：

  • 用 FAST action tokenizer 把 action chunk 变成离散 token
  • 直接走 PaliGemma 2B，做 next-token prediction
  • action_horizon=32，max_token_len=250
  • loss 是 token-level cross entropy，带 token_loss_mask
  • 推理是 KV-cache 自回归解码，最多 256 步，遇到 EOS 停
targets = jax.nn.one_hot(observation.tokenized_prompt[:, 1:], vocab_size)
pre_logits = self.PaliGemma.llm(embedded_prefix=input_token_embeddings[:, :-1], ...)
logits = self.PaliGemma.llm(pre_logits=pre_logits[:, -targets.shape[1]:])
logp = jax.nn.log_softmax(logits, axis=-1)
loss = -jnp.sum(targets * logp * loss_mask, axis=-1) / loss_mask.sum(-1)

5. π0.5 的差异

Pi0Config(pi05=True)：

  • state 变成离散语言 token，不再走 suffix 的 continuous state token
  • action expert 用 adaRMSNorm 注入 flow matching timestep
  • max_token_len=200
  • 仓库里 π0.5 只支持 flow matching head，不支持 FAST head

obs dict
  -> input transforms
  -> Observation

  -> output transforms

create_trained_policy 会自动判断 JAX 还是 PyTorch：有 model.safetensors 就是 PyTorch，否则加载 Orbax params。`serve_policy.py` 起 websocket server，默认端口 8000，机器人端用 openpi-client 连。

8. PyTorch 版

src/openpi/models_pytorch/pi0_pytorch.py:84   class PI0Pytorch

PyTorch 版是 π0 / π0.5 的移植，用 HuggingFace 的 PaliGemma + Gemma expert。几个关键点：

  • 需要打 transformers_replace patch（AdaRMS、精度控制、KV cache）
  • 支持 gradient checkpointing
  • 支持 torch.compile
  • 不支持 π0-FAST
  • 不支持 混合精度训练、FSDP、LoRA、EMA
