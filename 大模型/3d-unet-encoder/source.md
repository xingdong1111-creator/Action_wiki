# 3D U-Net：从 300 层 CT 到 3D 卷积与 Encoder 用法

> 目标：用一个具体例子搞清楚 3D U-Net 在做什么、3D 卷积到底怎么卷、能看多远，以及如果只想要一个 3D encoder，应该怎么用。

## 0. 一句话

**3D U-Net = 在 3D 体素/体积数据上做“下采样—上采样 + skip connection”的卷积网络。**

它不是把每一层切片单独处理，而是把 `D×H×W` 当成一个整体，利用层间连续性做分割、预测、重建或特征提取。

如果只想要 encoder，完全可以只用它的 encoder 部分：**输入体积，输出多尺度 3D 特征**。

---

## 1. 先建立直觉：300 张 CT 切片能干嘛

假设有 300 张 CT，每张形状是 `(1, 128, 128)`。

先分清两种情况：

- **情况 A**：同一个病人的连续 300 层；
- **情况 B**：300 个互不相关的 CT 图像。

只有情况 A 才天然适合 3D U-Net。情况 B 只是 300 张 2D 图，应该用 2D U-Net 或先组成体积。

### 1.1 把 300 层堆成一个体积

```python
# 每张切片: (1, 128, 128)
volume = np.stack(ct_slices, axis=0)   # (300, 1, 128, 128)
x = volume.transpose(1, 0, 2, 3)[None] # (1, 1, 300, 128, 128)
```

给 3D U-Net 的输入是：

```text
(B, C, D, H, W) = (1, 1, 300, 128, 128)
```

- `B=1`：一个病人；
- `C=1`：单通道灰度；
- `D=300`：300 层；
- `H=W=128`：每层 128×128。

### 1.2 输出是什么

以“肝脏 + 肿瘤”分割为例，输出通道设为 3：

```text
输入:  (1, 1, 300, 128, 128)
输出:  (1, 3, 300, 128, 128)
       │  │  │
       │  │  └─ H, W：和原来每层一样大
       │  └─ D：还是 300 层，每层都有预测
       └─ 3 个通道：背景 / 肝脏 / 肿瘤
```

也就是说，**不是只给你 300 张独立的分割图，而是给你一个完整的 3D 分割体积**。

网络里的形状大概这样变：

```text
input   (1,  1, 300, 128, 128)
down1   (1, 64, 150,  64,  64)
down2   (1,128, 75,  32,  32)
down3   (1,256, 37,  16,  16)   # bottleneck
up2     (1,128, 75,  32,  32)
up1     (1, 64, 150,  64, 64)
output  (1,  3, 300, 128, 128)
```

注意：`300 → 150 → 75 → 37`，75 是奇数，上采样回不去。工程上通常 pad 到 304、裁到 296，或者用 patch 训练。

### 1.3 分割完之后能算什么

假设：

- 像素间距：1 mm × 1 mm；
- 层厚：2 mm；
- 一个 voxel 体积：`1 × 1 × 2 = 2 mm³`；
- 肿瘤 mask 有 120,000 个 voxel。

那么：

```text
肿瘤体积 = 120000 × 2 mm³ = 240000 mm³ = 240 mL
```

还能得到：

- 肿瘤从第几层到第几层；
- 3D bounding box；
- 病灶数量（3D 连通域）；
- 每层肿瘤面积；
- 可旋转的 3D 病灶模型。

### 1.4 为什么 3D 比单层 2D 强

第 150 层有一个亮点，单看这一层，可能是肿瘤、血管断面、钙化点或噪声。

3D U-Net 会同时看第 149、151 层，甚至更远：

- 血管：连续多层呈管状延伸；
- 肿瘤：通常呈团块，形状和血管不同；
- 钙化/噪声：可能只在一两层出现。

所以它能减少“单层看不清就误判”的情况。

## 2. 3D 卷积到底怎么卷

### 2.1 维度定义

输入：

```text
(B, C_in, D, H, W)
```

卷积核：

```text
(C_out, C_in, kD, kH, kW)
```

输出：

```text
(B, C_out, D_out, H_out, W_out)
```

如果 stride=1、padding=1，则 `D_out=D`、`H_out=H`、`W_out=W`，尺寸不变。

### 2.2 一个输出体素是怎么算的

假设输入 `(1, 1, 300, 128, 128)`，卷积核 `(16, 1, 3, 3, 3)`，padding=1。

输出切片 `d` 上位置 `(h, w)` 的一个体素，会用到输入的小立方体：

```text
切片 d-1：3×3 区域
切片 d  ：3×3 区域（中心就在这里）
切片 d+1：3×3 区域
```

共 `3 × 3 × 3 = 27` 个输入体素。

```text
输出体素 = Σ（27 个体素 × 对应卷积核权重）+ bias
```

这是一个输出通道；`C_out=16` 就有 16 套不同的 `3×3×3` 卷积核。

所以一次卷积不是“把整层图卷一遍”，而是**在每个体素位置上，用一个小立方体在三维空间里滑动**。

### 2.3 一张图到底看前后几张

只看深度方向 `kD`：

| 卷积核深度 `kD` | 输出切片 `d` 看到的输入切片 |
|---|---|
| 1 | 只看 `d` |
| 3 | `d-1, d, d+1` |
| 5 | `d-2, d-1, d, d+1, d+2` |
| 7 | `d-3 ... d+3` |

最常用的 `3×3×3` 卷积，**每个输出体素只看前一层、当前层、后一层，共 3 层**。

几个容易混的点：

- `strideD=2`：输出每隔 2 层算一次，但每个输出点仍看 3 层，只是计算位置变稀。
- `dilationD=2`：如果 `kD=3`，会看 `d-2, d, d+2`，中间隔一层。
- `kD=1`：完全不看上下层，深度方向没有信息混合。

## 3. 感受野：单层到多层

单层只能看 3 层，但多层叠加 + 下采样后，感受野会变大。

### 3.1 公式

只看深度方向：

```text
r_new = r_old + (k - 1) × J_old
J_new = J_old × stride
```

- `r`：当前能看到多少层原始切片；
- `J`：当前特征图上一层相当于原始几层的步长；
- `k`：这一层卷积核深度。

### 3.2 一个具体计算

假设每个尺度两个 `3×3×3` 卷积，然后 `MaxPool3d(2)`：

```text
初始: r=1, J=1

Level 1:
  conv3x3x3: r=3,  J=1
  conv3x3x3: r=5,  J=1
  pool2:     r=6,  J=2

Level 2:
  conv3x3x3: r=10, J=2
  conv3x3x3: r=14, J=2
  pool2:     r=16, J=4

Level 3:
  conv3x3x3: r=24, J=4
  conv3x3x3: r=32, J=4
  pool2:     r=36, J=8

Bottleneck:
  conv3x3x3: r=52, J=8
  conv3x3x3: r=68, J=8
```

到 bottleneck，**理论上一个点能看到约 68 层原始切片**。这是理论感受野，实际网络学到多少是另一回事。

所以：

- 单层 `3×3×3`：前后各 1 层；
- 叠几层 + 下采样后：几十层；
- 一般不会靠 3D 卷积直接看完整 300 层，太贵，也没必要。

### 3.3 300 层 CT 怎么办

3D U-Net 不是让每个点都看到整卷，而是：

- 浅层：看局部几层，抓边缘、纹理；
- 深层：看几十层，抓器官/病灶的大形状；
- decoder + skip：把全局语义和局部细节合起来。

如果一定要看整卷，通常靠：

- 更大的 `kD` 或 dilation；
- 更多下采样；
- 3D attention / transformer；
- coarse-to-fine：先看低分辨率整卷，再看局部高分辨率。

## 4. 3D U-Net 当 Encoder 用

可以，而且很常见。**只用 U-Net 的 encoder 部分，不要把 decoder 也带着。** 它本质就是一个多尺度 3D 特征提取器。

### 4.1 Encoder 输出什么

还是输入 `(1, 1, 300, 128, 128)`，encoder 跑完得到两类东西：

1. **Bottleneck 特征图**：比如 `(1, 256, 37, 16, 16)`
   - 语义强、分辨率低；
   - 适合表示“这个体积里有什么、大概在哪”。
2. **中间层 skip 特征**：比如 `(1, 128, 75, 32, 32)`、`(1, 64, 150, 64, 64)`
   - 分辨率高、细节多；
   - 适合接 decoder 或做精细定位。

如果只要一个 encoder，**不要只盯着 bottleneck**，有时中间层更有用。

### 4.2 用法 1：全局 embedding，做分类/检索

最简单：bottleneck 后面接全局池化 + MLP。

```python
feat = encoder(x)                    # (B, 256, 37, 16, 16)
z = F.adaptive_avg_pool3d(feat, 1)   # (B, 256, 1, 1, 1)
z = z.flatten(1)                     # (B, 256)
logits = mlp(z)                      # 分类/回归/检索
```

适合做：

- 这个 CT 有没有肿瘤；
- 属于哪种疾病/分型；
- 两个体积像不像（metric learning）。

### 4.3 用法 2：3D 特征图，接 decoder / world model

把 bottleneck 或中间层特征交给后续模块：

```text
3D U-Net encoder → 3D latent feature → dynamics / decoder / predictor
```

比如：

- 预测下一时刻的 3D occupancy；
- 作为 3D VAE 的 encoder；
- 作为视频/世界模型的视觉编码器。

这种情况下，**保留 3D 网格结构**比压成一个向量更重要。

### 4.4 用法 3：给 LLM 的视觉 token

这是它和 LLM 结合最常见的位置：

```text
3D volume → 3D U-Net encoder → 3D tokens → projector → LLM
```

以 bottleneck `(1, 256, 37, 16, 16)` 为例：

```python
feat = encoder(x)                       # (1, 256, 37, 16, 16)
tokens = feat.flatten(2).transpose(1, 2) # (1, 9472, 256)
tokens = projector(tokens)              # 映射到 LLM hidden size
```

但这里有两个问题：

- **token 太多**：9472 个 token 直接喂 LLM 很贵；
- **没有位置信息**：LLM 不知道每个 token 在体积里的位置。

所以通常要加：

- 3D 位置编码；
- 进一步池化/降采样，或者 learnable query，把 token 压到 64/128 个。

比如：

```text
(1, 256, 37, 16, 16)
 → 3D pooling 到 (1, 256, 8, 8, 8)
 → 512 个 token
 → 加 3D 位置编码
 → projector → LLM
```

### 4.5 代码骨架

```python
class UNet3dEncoder(nn.Module):
    def __init__(self, in_ch=1, base=32):
        super().__init__()
        self.inc = DoubleConv3d(in_ch, base)
        self.d1 = Down3d(base, base * 2)
        self.d2 = Down3d(base * 2, base * 4)
        self.d3 = Down3d(base * 4, base * 8)

    def forward(self, x):
        x1 = self.inc(x)   # 高分辨率细节
        x2 = self.d1(x1)
        x3 = self.d2(x2)
        x4 = self.d3(x3)   # bottleneck 语义
        return {"bottleneck": x4, "mid": x3, "shallow": x2, "detail": x1}
```

然后按用途选：

```python
feats = encoder(x)

# 分类：只用 bottleneck + 全局池化
z = F.adaptive_avg_pool3d(feats["bottleneck"], 1).flatten(1)

# 接 LLM：用 bottleneck 或 mid，压 token 后投影
tokens = feats["mid"].flatten(2).transpose(1, 2)
```

### 4.6 优点和局限

**优点：**

- 多尺度特征天然适合 3D 数据；
- 比从头搭一个 3D CNN 省事；
- 可以先用分割/重建任务预训练，特征比较通用；
- 小数据上通常比纯 Transformer 更容易训练。

**局限：**

- 没有全局 attention，长程空间关系要靠深层感受野；
- 直接输出 3D 网格，接 LLM 要处理 token 数和位置编码；
- 它自己不懂语言，需要 projector/对齐训练；
- 如果只要一个全局向量，3D ResNet 之类可能更简单。

## 5. 实践建议

1. **先决定输出形态**：要一个向量、一个 3D 特征图，还是一串 LLM token，然后只取对应层。
2. **预训练**：先用分割/重建任务预训练 encoder，再接下游头；先冻结，再解冻。
3. **显存**：3D 卷积很吃显存，优先 patch training、混合精度、gradient checkpointing。
4. **尺寸**：`D/H/W` 要能被下采样次数整除；不能整除就 pad/crop。
5. **小体积**：`32×32×32` 或 `64×64×64` 的 patch 足够验证方法，不要一上来 `300×128×128`。
6. **归一化**：batch 很小时，`InstanceNorm3d` 或 `GroupNorm` 通常比 `BatchNorm3d` 稳。
7. **数据增强**：随机翻转、旋转 90°、弹性变形、gamma、噪声；医学数据不要做破坏解剖结构的强仿射。

---

## 6. 小结

- **3D U-Net** 把 2D U-Net 的卷积、池化、上采样换成 3D，用来处理体积数据。
- **300 层 CT** 可以堆成 `(1,1,300,128,128)`，输出一个完整的 3D 分割体积，还能算病灶体积、层范围和连通域。
- **`3×3×3` 卷积**一次只看前后各 1 层；多层叠加 + 下采样后，深层点可以看到几十层。
- **当 encoder 用**很合适：可以输出全局向量、3D 特征图，或给 LLM 的 token；关键是只取需要的层，并处理好 token 数和 3D 位置编码。
